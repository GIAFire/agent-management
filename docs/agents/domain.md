# 领域文档

工程 skill 在探索代码库时，应按本文规则读取本仓库的领域文档。

## 探索代码前需要读取

- 根目录下的 **`CONTEXT.md`**。
- 如果根目录存在 **`CONTEXT-MAP.md`**，则改为读取该文件指向的、与当前工作相关的各个 `CONTEXT.md`。
- **`docs/adr/`** 中与即将处理区域相关的 ADR。在多上下文仓库中，还需检查 `src/<上下文>/docs/adr/` 中特定于上下文的决策。

如果上述文件不存在，**直接继续，不作提示**。不要报告文件缺失，也不要预先建议创建。`domain-modeling` skill（可通过 `grill-with-docs` 和 `improve-codebase-architecture` 使用）会在术语或决策真正得到确认时按需创建这些文件。

## 文件结构

本仓库采用单一上下文：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-示例决策.md
│   └── 0002-另一项示例决策.md
├── pom.xml
├── common/
├── gateway/
├── auth/
└── service-modules/
```

即使项目包含多个 Maven 模块，领域文档仍统一维护在根目录的 `CONTEXT.md` 中，系统与模块相关的 ADR 均统一放在根目录的 `docs/adr/` 中。

## 使用术语表中的词汇

当输出内容需要命名领域概念时（例如 Issue 标题、重构建议、假设或测试名称），应使用 `CONTEXT.md` 中定义的术语。不要改用术语表明确避免的同义词。

如果所需概念尚未出现在术语表中，这通常意味着正在使用项目中不存在的语言，应重新考虑；也可能表示领域模型存在真实缺口，应记录下来并交由 `domain-modeling` skill 处理。

## 标明与 ADR 的冲突

如果输出内容与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> 与 ADR-0007（示例决策）冲突，但值得重新讨论，因为……
