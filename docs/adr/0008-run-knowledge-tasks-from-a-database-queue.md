# 使用数据库队列执行知识任务

知识任务持久化在 MySQL，由 Spring 定时工作器通过租约认领并交给受控线程池执行，以在不引入 RabbitMQ 或 Kafka 的情况下支持多实例互斥、进度查询和服务重启恢复；MySQL 是唯一排队位置，工作器只有先取得本地线程执行许可才会认领任务，不在本地队列中提前持有租约。任务表记录状态、阶段、请求快照、错误和租约信息。每次认领使用唯一租约令牌，避免同一实例中的旧工作线程越过新的清理执行。任务只执行一次，任何错误都直接进入 `FAILED` 并记录原因，不做自动重试；用户排除问题后可手动重新提交为一条新任务，并保留失败历史。服务重启后尚未执行的 `PENDING` 任务可继续认领；租约过期的 `RUNNING` 任务在保持活动状态和并发唯一约束期间先清理未完成产物，再标记为因执行中断而失败，不自动重新执行。
