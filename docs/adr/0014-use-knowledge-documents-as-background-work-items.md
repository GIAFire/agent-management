# 使用知识文档承载后台处理状态

知识文档的切片入库和删除不再创建独立知识任务。提交事务成功后，应用立即将对应文档投递到本地受控线程池，执行器通过文档租约原子认领后异步处理；应用启动时仅执行一次遗留 `PENDING`、`DELETING` 和过期租约恢复，不使用 Spring 定时任务持续扫描数据库。系统删除 `ai_knowledge_task`、知识任务接口、任务历史以及前后端自动轮询，提交切片接口直接返回知识文档，用户通过手动刷新文档列表查看当前状态；切片失败使用 `FAILED`，删除失败使用 `DELETE_FAILED`，失败后均由用户从知识文档操作入口手动重试。

该方案避免周期性数据库查询，代价是应用在数据库事务提交后、进程内投递完成前崩溃时，文档只能在下次应用启动时恢复；仍在有效租约期内的中断处理也要等租约过期后的下一次启动才能恢复。若将来需要跨实例、无轮询且具备实时故障转移的可靠派发，应引入 RabbitMQ、Kafka 等消息队列。知识切片只关联知识文档，不保存知识任务标识；数据库结构变更由部署方显式执行，不由应用在运行时自动迁移。
